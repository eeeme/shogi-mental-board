# 課金（買い切り）方針メモ ※今は実装しない・記録のみ

現フェーズでは**実装しない**。判定の抽象化（`src/lib/entitlement.ts` の `useEntitlement()`）だけ用意し、
将来ここを差し替える。以下は将来の実装方針の記録。

## 前提

- **アプリ内課金はストア公開が前提**。今の PWA(GitHub Pages) のままでは実装できない。
  → **Capacitor でネイティブ化**してから対応する。
- 「バックエンドなし」の設計は維持する。

## 採用予定

- **RevenueCat** を使う。
  - レシート検証をサーバーレスで賄えるため、バックエンドなしの設計を維持できる。
  - iOS/Android を1つのAPIで扱える。個人開発の規模なら**無料枠で十分**。
- 商品種別は **非消費型（Non-Consumable）の買い切り**。**サブスクは採用しない**。
- **「購入を復元」ボタンは必須**（無いと Apple の審査で落ちる）。

## 無料 / 有料の切り分け（将来有効化）

| 対象 | 扱い |
|---|---|
| 00 ただ読み上げ | 常に無料・無制限 |
| 01〜03 | 1日3回まで無料、それ以上はアンロックが必要 |
| バックグラウンド再生 | 有料機能 |

- 現状は `useEntitlement()` が常に `{ isPro: false }` を返すダミー。
- 1日3回のカウント／日付リセットは `src/lib/usage.ts` の純粋関数（テスト済み）＋ localStorage。
- **今は判定を通すだけで、実際のブロックはしない**（CTAを出せる構造だけ用意）。
- 課金導入時は `useEntitlement()` の中身を RevenueCat に差し替え、モード説明ポップアップの
  課金CTAスロットに購入導線を差し込む。
