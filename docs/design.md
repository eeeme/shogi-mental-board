# 将棋 脳内盤トレーニングアプリ — 全体設計書（自分専用MVP版）

## 0. この設計の前提

- **目的（当面）**: まず自分専用のトレーニングツールとして完成させる。ストア展開・課金・広告は将来拡張として切り離す。
- **開発フロー**: english-app と同じく Linear（Issue管理）× Claude Code（実装）× GitHub（PR/マージ）。出社中のスキマにスマホから進められる形を維持。
- **設計思想**: 自分専用のうちは最小構成。バックエンドを持たず、全機能をクライアントだけで完結させる（english-app より更に軽い）。

---

## 1. 技術スタック

| 領域 | 採用 | 理由 |
|---|---|---|
| クライアント | React + TypeScript + Vite | 型安全・軽量・Claude Code と好相性。english-app の PWA 路線と統一 |
| 形態 | PWA（インストール可能なWebアプリ） | 1ユーザーならこれで十分。スマホにも入る |
| 音声読み上げ | Web Speech API（`speechSynthesis`） | ブラウザ標準・追加コストゼロ・日本語音声あり |
| 状態管理 | Zustand（軽量） or React Context | 規模が小さいので重い管理は不要 |
| ローカル保存 | IndexedDB（統計） / localStorage（設定） | 端末内完結。サーバー不要 |
| スタイル | Tailwind CSS | 盤面グリッドを素早く組める |
| デプロイ | 静的ホスティング（GitHub Pages / Vercel / Render 静的） | 完全クライアントなので静的でよい |

**将来のストア展開パス**: PWA を Capacitor でネイティブ（iOS/Android）にラップすれば、コードを再利用したまま両ストアに出せる。今は「その道を塞がない」だけ確保しておく。

**補足**: Python が得意でも、モバイル前提のこのアプリは Web/TS が最短。バックエンドが必要になる将来（アカウント同期・詰将棋問題の配信）まで Python(FastAPI) の出番は温存。

## 2. 最重要論点：将棋符号の読み上げ

全機能が「座標を音声で言う／答える」に依存するため、**符号→読み仮名の変換が土台**になる。

- 盤の座標系：**筋（すじ）= 縦列、右から 1〜9** ／ **段（だん）= 横行、上から 一〜九**。マス表記は「筋段」（例：７六 = 7筋6段）。
- TTS に `"７六"` や `"76"` をそのまま渡すと正しく読めない。**ひらがなの読み（例 `"ななろく"`）を生成して渡す**。
- 数字の読みには流派があるため、設定で切替可能にする：
  - 4 → 「よん」/「し」
  - 7 → 「なな」/「しち」
  - 9 → 「きゅう」/「く」
- 実装は純粋関数の変換テーブルにする（テスト容易）:

```ts
// 例（イメージ）
type Yomi = "modern" | "classic";
function fileYomi(file: number, style: Yomi): string { /* 1..9 → よみ */ }
function rankYomi(rank: number, style: Yomi): string { /* 1..9 → よみ */ }
function cellYomi(file: number, rank: number, style: Yomi): string {
  return fileYomi(file, style) + rankYomi(rank, style); // 例 "ななろく"
}
```

- TTS ラッパーで話速・声の選択・連続発話のキュー管理をまとめる（`speak(text, {rate})`）。
- iOS Safari は「ユーザー操作起点でないと音声が出ない」制約があるため、**開始ボタンを踏ませてから発話を始める**設計にする。

## 3. 画面構成

```
[ホーム] ── 機能カードを一覧表示、タップで各機能へ
  ├─ 読み上げ→マス押下
  ├─ マスが光る→記号を答える（逆変換）
  ├─ ただ読み上げ（受動トレーニング）
  ├─ ランダム配置記憶
  ├─ 詰将棋（見ずに解く）
  ├─ 統計
  └─ 支援（お涙頂戴）
[設定] ── TTS話速 / 読みの流派 / 盤の向き（先手・後手視点）
```

- ボトムナビは english-app と同じ思想でシンプルに（例：ホーム / 統計 / 設定 の3タブ）。
- 各機能画面は「開始 → 出題ループ → 結果サマリ」の共通フローに揃える。

## 4. 共通コンポーネント / ユーティリティ

| 名前 | 役割 |
|---|---|
| `ShogiBoard` | 9×9グリッド。マスのタップ検出、任意マスのハイライト、駒の向き付き描画（先手＝上向き/後手＝反転）に対応 |
| `ttsSpeak` | 符号読み変換＋`speechSynthesis`ラッパー（話速・キュー管理） |
| `coords` | 筋段 ⇔ インデックス ⇔ 読み仮名 の相互変換（純粋関数・要ユニットテスト） |
| `SessionRecorder` | 1試行ごとに {出題, 回答, 正誤, 反応時間ms} を記録し、終了時にIndexedDBへ保存 |
| `useSettings` | 話速・読み流派・盤の向きを localStorage で永続化 |

## 5. 機能別設計

### ① 読み上げ→マス押下（系列記憶→順番再現）
- TTSが座標を **N個** 順に発話（例「ななろく」「さんし」「はちきゅう」）→ ユーザーは脳内で記憶 → 読み終わったら、**鳴った順に N個のマスをタップ** → 位置と順序が合っているか判定。
- 1個ずつ即答するのではなく、N個ためて系列で再現する。ワーキングメモリ（系列記憶）＋脳内盤の訓練。
- パラメータ：出題数 N（自分で設定）、出題範囲（全盤 / 一部の筋段に限定）、話速。
- 記録：N＝難易度、順序・位置の一致数、所要時間、間違えやすいマスのヒートマップ。
- **判定は「順序も一致」で正解**（位置だけの部分点ではなく、鳴った順に正しく再現できて正解。所要時間・部分一致は記録として残す）。

### ② マスが光る→記号を答える（逆変換）
- 盤上のランダム1マスをハイライト → ユーザーが座標を回答。
- 回答UI：筋ピッカー＋段ピッカー（初期）。将来は音声認識も検討。
- ①の逆。位置→符号の変換を鍛える。

### ③ ただ読み上げ（受動トレーニング）
- 連続で座標を読み上げるだけ。画面を見ず「ながら」でOK。
- パラメータ：**スピード（発話間隔）／出題範囲（マス数・盤の一部）／連続数**。← ここの可変性が本アプリの差別化点。
- 実装が最も軽く、TTS基盤の検証を兼ねられる → **最初に作る機能**。

### ④ ランダム配置記憶
- 先手・後手が **交互にランダムなマスへランダムな駒を打つ**（＝置くだけ。移動ではない）。1手ごとに音声/表示で「先手、歩、ななろく」等 → 置き終わったら盤を隠す → **最終盤面を再現**（各マスの位置＋向き＋駒種のすべてを当てる）。
- 旧「駒移動追跡」を廃止して置換。**駒の動きの定義・合法手生成・AIが不要**（打つだけなので二歩等の反則は記憶訓練上は無視でよい）。
- **向き（先手＝上向き / 後手＝反転）と駒種を必ず問う**のがこのモードの肝。盤面を向き・種類込みで記憶する力を鍛える。
- 回答UI：盤の各マスをタップして駒種・向きを指定。駒種選択が入るため **UIは重くなる。よって初回ローンチには含めず後続フェーズで実装**する。
- パラメータ：総枚数（難易度）、使う駒種。
- 記録：枚数＝難易度、位置＋向き＋種類まで正しく再現できたマス数。

### ⑤ 詰将棋（見ずに解く）
- 攻方・玉方の配置と持ち駒を音声で読み上げ → 詰み手順を回答。
- 問題データは JSON で同梱（KIF由来を変換）。**1〜3手詰から少数で開始**。
- コンテンツ調達がボトルネックなので **後半フェーズ**。まず自作の数問＋短手詰から。

### ⑥ 統計
- 各機能の：正答率 / 平均反応時間 / 試行数 / 日別推移 / 連続日数（ストリーク）。
- IndexedDB のセッション記録を集計してグラフ表示。
- 「弱点マス」や、系列記憶で崩れ始める N・配置記憶で崩れ始める枚数を可視化し、次の出題に反映できると理想。

### ⑦ 支援（お涙頂戴）
- 自分専用版ではプレースホルダ（将来の投げ銭リンク置き場）。
- ストア版で「価値を感じた後に目に入る場所（アンロック後のお礼画面等）」へ設置。

## 6. データモデル（クライアント内）

```ts
type Cell = { file: number; rank: number }; // 1..9 / 1..9

type Trial = {
  prompt: string;      // 出題（符号や手順）
  answer: string;      // ユーザー回答
  correct: boolean;
  ms: number;          // 反応時間
};

type Session = {
  id: string;
  mode: "tap" | "reverse" | "listen" | "recall" | "tsume";
  // tap=系列記憶タップ / reverse=逆変換 / listen=ただ読み上げ / recall=ランダム配置記憶 / tsume=詰将棋
  startedAt: number;
  finishedAt: number;
  trials: Trial[];
};

type Settings = {
  rate: number;              // TTS話速
  yomiStyle: "modern" | "classic";
  boardOrientation: "sente" | "gote";
};
```

- Session を IndexedDB に蓄積 → 統計はここから集計。
- Settings は localStorage。

## 9. 論点メモ（後で決める）

- 段の読み上げ流派（なな/しち 等）のデフォルトをどれにするか。
- ①系列記憶：判定は「順序も一致で正解」に決定。N の既定レンジ（例 3〜7）は要調整。
- ②逆変換の回答UI：ピッカー vs 盤タップで「筋・段の目盛」を選ばせる vs 音声認識。
- ④ランダム配置記憶：位置＋向き＋駒種まで当てさせる（重い版）に決定。初回ローンチには入れず後続フェーズで実装。
- ⑤詰将棋の問題フォーマット（自作JSON / KIF読み込み / 既存問題集の利用可否）。
- 統計の「弱点に応じた出題調整」をMVPに入れるか将来にするか。
